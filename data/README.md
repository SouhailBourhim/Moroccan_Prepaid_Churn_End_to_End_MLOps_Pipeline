# Data Directory

Raw data is **not committed to git** — it is tracked via DVC.  
Generated files under `features/` are also gitignored (reproduced by `python -m src.features.run_pipeline`).

## Layout

```
data/
  raw/
    expresso/          ← PRIMARY training dataset (Zindi)
      Train.csv              2,154,048 rows × 19 cols
      Test.csv                 380,127 rows × 18 cols
      VariableDefinitions.csv
    cell2cell/         ← REFERENCE dataset (EDA / cross-dataset validation only)
      cell2celltrain.csv        51,047 rows × 58 cols
      cell2cellholdout.csv      20,000 rows × 58 cols
    orange/            ← REFERENCE dataset (EDA / cross-dataset validation only)
      churn-bigml-80.csv         2,666 rows × 20 cols
      churn-bigml-20.csv           667 rows × 20 cols
  features/            ← generated by src/features/run_pipeline.py
    train_features.parquet    2,154,048 rows × 45 cols (44 features + CHURN)  54 MB
    test_features.parquet       380,127 rows × 44 cols                         23 MB
    feature_pipeline.pkl      fitted FeaturePipeline — load with joblib for inference
    feature_stats.csv         per-feature: null rate, pct_zero, mean, std, Spearman ρ
    feature_manifest.json     feature names list, churn rate, row counts
  processed/           ← intermediate outputs (not currently used)
  interim/             ← scratch / exploration files (not tracked)
```

## Dataset Roles

| Dataset | Role | Used for training? |
|---------|------|--------------------|
| `expresso/` | Primary | Yes — all model training and evaluation |
| `cell2cell/` | Reference | No — EDA and cross-dataset feature validation only |
| `orange/` | Reference | No — EDA and cross-dataset feature validation only |

The reference datasets establish which feature *concepts* predict churn across different operators and geographies. See `notebooks/04_cross_dataset_analysis.ipynb` for the full robustness analysis and `notebooks/05_feature_engineering.ipynb` for how those findings shaped the Expresso feature set.

### Missingness patterns

**MNAR (Missing Not At Random)** — high missingness columns are absent because the subscriber never used that service. This is itself predictive: churn rate is 2–10× higher when these are missing. The pipeline adds `{col}_missing` indicator flags *before* imputing 0.

| Group | Columns | Missing % | Churn lift when missing |
|-------|---------|-----------|------------------------|
| MNAR — usage | `DATA_VOLUME` | 49.2% | 4.2× |
| MNAR — network | `ON_NET`, `ORANGE`, `TIGO` | 37–60% | 8–10× |
| MNAR — international | `ZONE1`, `ZONE2` | 92–94% | 4.5× |
| MNAR — pack | `TOP_PACK`, `FREQ_TOP_PACK` | 41.9% | 9.7× |
| MAR | `MONTANT`, `FREQUENCE_RECH`, `REVENUE`, `ARPU_SEGMENT`, `FREQUENCE` | 34–35% | 8–9× |
| MAR — geographic | `REGION` | 39.4% | 2.5× |

**Collinearity**: `REVENUE ≡ ARPU_SEGMENT × 3` (Spearman ρ = 1.00). Both columns and both missing flags are dropped from the model feature set; `REVENUE` and `REVENUE_missing` are kept.

## Engineered Feature Reference

Produced by `FeaturePipeline` in `src/features/build_features.py`. Full decision rationale in `notebooks/05_feature_engineering.ipynb`.

### Missing indicator flags (14 features)

Binary (0/1). Created before imputation so the absence signal is not lost.

`REGION_missing`, `MONTANT_missing`, `FREQUENCE_RECH_missing`, `REVENUE_missing`, `FREQUENCE_missing`, `DATA_VOLUME_missing`, `ON_NET_missing`, `ORANGE_missing`, `TIGO_missing`, `ZONE1_missing`, `ZONE2_missing`, `TOP_PACK_missing`, `FREQ_TOP_PACK_missing`

Note: `ARPU_SEGMENT_missing` is computed but **dropped** — it is identical to `REVENUE_missing`.

### Service absence features (2 features — new)

Motivated by cross-dataset EDA: customer service calls are the dominant churn predictor in Orange and Cell2Cell but absent from Expresso. Subscribers who use almost no services map to the same disengaged segment.

| Feature | Description | Spearman ρ |
|---------|-------------|-----------|
| `n_services_absent` | Count of MNAR service channels originally missing [0–7] | 0.47 |
| `is_ghost_subscriber` | 1 if `n_services_absent` ≥ 5 (uses almost nothing) | 0.46 |

### Raw usage features (12 features, post-imputation)

`MONTANT`, `FREQUENCE_RECH`, `REVENUE`, `FREQUENCE`, `DATA_VOLUME`, `ON_NET`, `ORANGE`, `TIGO`, `ZONE1`, `ZONE2`, `REGULARITY`, `FREQ_TOP_PACK`

### Engineered numeric features (11 features)

| Feature | Formula | Spearman ρ | Note |
|---------|---------|-----------|------|
| `regularity_rate` | REGULARITY / 90 | −0.53 | Normalised activity ratio |
| `recharge_per_freq` | MONTANT / (FREQUENCE_RECH + 1) | −0.38 | Value per recharge event |
| `revenue_per_freq` | REVENUE / (FREQUENCE + 1) | −0.37 | Revenue efficiency |
| `data_per_freq` | DATA_VOLUME / (FREQUENCE + 1) | −0.19 | Data intensity per transaction |
| `total_calls` | ON_NET + ORANGE + TIGO + ZONE1 + ZONE2 | −0.45 | Aggregate call volume |
| `intl_calls` | ZONE1 + ZONE2 | −0.10 | International calls (separated for interpretability) |
| `n_active_call_types` | Count of non-zero call channels [0–5] | −0.45 | Network breadth |
| `is_inactive` | REGULARITY < 5 | 0.54 | Extreme inactivity flag |
| `has_data` | DATA_VOLUME > 0 | −0.31 | Data service adopted |
| `has_calls` | total_calls > 0 | −0.48 | Any call activity |
| `has_intl_usage` | intl_calls > 0 | −0.09 | International usage indicator |
